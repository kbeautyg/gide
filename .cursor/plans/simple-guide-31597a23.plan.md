# Глобальный план упрощения системы до единого кабинета гида

## Подготовка и анализ

- Провести ревизию текущего состояния репозитория: проверить незакоммиченные изменения, активные миграции, содержимое `seed_data.py`, актуальные маршруты во фронтенде.
- Зафиксировать текущие требования: единственный личный кабинет для роли гида, уникальные непубличные ссылки `/t/{code}`, офлайн-учёт оплат, навигация из макета, stat-блоки и график доходов за 30 дней, публичный лендинг "Стать гидом".
- Уточнить существующие данные/миграции на Railway: экспортировать схему БД, убедиться что текущий деплой использует ту же версию кода (важно для миграций share_code).
- Подготовить список устаревших страниц/компонентов и эндпоинтов, которые предстоит удалить (включая роли админов, супер-менеджеров и т.п.).

- Обновить зависимости в `app/api` (авторизация endpoints), убрать все проверки на роли выше гида.
- Привести сидеры/фикстуры к созданию только гида.

### 2. Очистка кабинета и API

- Удалить/скомментировать эндпоинты, связанные с управлением командами, назначением ролей, просмотром пользователей (все `/admin/…` маршруты).
- Проверить, что фронтенд не вызывает удалённые маршруты (иначе вернуть заглушки или заглушить запросы).

### 3. Поддержка уникальных ссылок экскурсии

- Обновить модель `Tour` (`backend/app/models/tour.py`): добавить колонку `share_code` (String(8), unique, index, nullable=False при создании), убедиться что длина и формат соответствуют выбранному короткому коду.
- Создать Alembic-миграцию: `op.add_column('tours', sa.Column('share_code', sa.String(length=8), nullable=True))`, затем заполнить существующие записи уникальными кодами (`op.execute`), после чего сделать `nullable=False`; создать индекс `op.create_index('ix_tours_share_code', 'tours', ['share_code'], unique=True)`.
- В `TourService.create_tour`: генерировать короткий код (например, `uuid.uuid4().hex[:8]`), проверять уникальность в цикле, присваивать при создании.
- Добавить метод `get_tour_by_share_code` с `select(Tour).where(Tour.share_code == code)` и `selectinload(Tour.guide)`.
- Обновить сериализаторы/схемы Pydantic для тура, чтобы возвращать `share_code`.

### 4. Публичный эндпоинт по коду и статистика

- В `backend/app/api/v1/endpoints/tours.py`:
- Импортировать `select`, `func` и модель `Booking`.
- Добавить `GET /tours/by-code/{share_code}`: без авторизации, возвращает полную информацию о туре + статы (кол-во оплат, сумма).
- Модифицировать `GET /tours/` и `GET /tours/{id}`: присоединять статистику бронирований (кол-во подтверждённых оплат и суммарный доход) через отдельные запросы или join + агрегаты.
- Убедиться, что публичный каталог `/tours` может вернуть пустой список, но API должен корректно работать.

### 5. Офлайн оплата и статистика доходов

- Создать Pydantic-схему `OfflinePaymentCreate` (tour_id, имя/телефон/email клиента, сумма, валюта, дата оплаты).
- Добавить новый роут `POST /bookings/offline-payment`: доступен гиду, создаёт запись `Booking` со статусом `paid`, привязывает к туру, сохраняет данные клиента; обновляет баланс гида (например, `balance_rub`).
- Добавить `GET /bookings/revenue-stats?days=30`: возвращает массив из 30 элементов с датой и суммой за день. Использовать `func.date_trunc('day', Booking.paid_at)` и группировку.
- Актуализировать модель `Booking` (при необходимости добавить `paid_at` или использовать существующие поля).
- Обновить сервисы, чтобы при создании онлайн/офлайн-оплаты обновлялся баланс гида/статистика.

### 6. Запросы и CORS

- В `backend/app/api/v1/endpoints/requests.py` разрешить создание заявок всем аутентифицированным пользователям (конкретно гиду); убрать проверки ролей.
- Обновить `backend/app/main.py` CORS-мидлварь: добавить Railway-домен фронтенда, локальные URL.

### 7. Очистка данных

- В `seed_data.py` убрать автогенерацию тестовых экскурсий; оставить опциональные фикстуры или добавить флаг.
- Проверить другие места, где могли создаваться мок-данные (`tours.py` и пр.), удалить их.
